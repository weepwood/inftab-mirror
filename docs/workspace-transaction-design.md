# 工作区事务持久化设计与迁移门禁

## 已实现的底层契约
- 独立 IndexedDB 数据库；同一个 readwrite transaction 检查 expected revision，并更新 head 与 previous。
- 两个标签页使用同一 revision 提交时，只有一个成功。另一方必须重新读取并明确解决冲突。
- 严格 durability 提示（浏览器不支持时回退默认）；等待 transaction complete 才报告提交成功。
- previous 保留上一份快照，显式恢复通过新 revision 写入。单快照限制 8 MiB。读写结束关闭连接，阻塞后迟到连接关闭。
- 实际 Chromium 测试通过两页面竞争、重载、注入 quota 错误验证回滚契约；测试结果以 CI 为准。

## V2.0 生产桌面事务恢复
- 独立 IndexedDB 数据库 `inftab-desktop-transactions` 保存四个入口键的事务前后值，单槽和 8 MiB 限制，先持久化意图，再同步刷新及核对兼容键。
- 未完成的操作禁止发起新桌面事务，显示继续、回退、保留当前已持久化数据的明确选择。只回放仍匹配已知前后值的记录，检测未知值拒绝覆盖；恢复前提示导出备份并关闭其他编辑标签页。
- 支持 Web Locks 的协作标签互斥；旧版、经典模式和其他普通编辑未统一进入此锁。旧 localStorage 键不具备跨键原子性；意图记录不是全工作区权威数据库。
- 本机及跨浏览器测试验证锁竞争、写入意图失败、部分写入、重载后的继续/回退及外部冲突拒绝。

## V2.1 迁移候选预检（未切换权威源）
- 设置 → 数据 → 存储可靠性：按需加载；显式检查并保存单份独立候选。保留 14 个工作区原始键、桌面模式、旧天气键、历史桌面坐标键，以及当前逻辑备份；原始值与当前逻辑值差异、解析规范化及不在范围的键均提示，不自动修正或覆盖。损坏 JSON 停止；整体上限 8 MiB。
- 独立 IndexedDB 数据库 `inftab-storage-preflight` 的 `candidates/latest` 使用候选 ID CAS；提交前检查原始键与逻辑快照，事务后回读一致性；来源随后变化时必须重新检查。候选不是自动同步的备份，不持有生产写入权。
- 未完成桌面事务阻止检查与保存；删除候选只删除独立记录；不清空旧数据，不写入旧 journal 的 head，不发送数据到网络。
- 旧版可能绕开新写入协议，因此后续切换方案需要旧客户端隔离、迁移世代标识、可中断初始化和明确回退，不能把候选直接升级为权威快照。独立候选仅为迁移准备及验证。

## V2.1 隔离世代与冲突规划契约
- 独立数据库 inftab-workspace-generation / generations / latest；每一世代使用随机 ID 和单调 revision，prepared → rehearsal → retired，准备/提交/回退/退役均在单个 IDB readwrite 事务中 CAS；初始原候选、head、previous 保留，单候选及单快照分别限制 8 MiB。回退产生新 revision；退役后旧令牌失效，替换含独立草稿的退役世代必须显式确认，且应先导出草稿。
- 初始快照经真实 parseWorkspaceBackup 验证；若规范化改变数据，必须明确接受，仍保留原候选；后续提交拒绝任何隐式规范化。未完成桌面事务阻止演练写入。检测旧 localStorage 原始键变化时拒绝启动/提交/回退，保留隔离草稿及原始数据；退役不修改任一来源。旧客户端不能被新客户端强制锁定，检测只覆盖已知原始键，不承诺原子跨库隔离、无变化窗口或强制禁止旧客户端写入。隔离演练不具备生产权威写入权。
- 独立三方冲突规划器：递归处理不同字段、按 ID 合并记录，保留双方插入锚点；重叠修改、删除/修改、不可兼容顺序、规范化或引用校验导致的隐式修复全部返回冲突，不生成可提交快照。规划器尚未连接实际编辑/提交 UI，不自动解决冲突。
- E2E 使用现有 Vite 构建独立测试模块并在真实浏览器执行真实解析器与 IDB；从实际预检界面生成候选。测试注入的 getBackup 返回已保存逻辑候选，实时来源比较仍读取真实 localStorage；尚未验证未来生产适配器的实时响应式快照接线。该独立测试模块不加入生产图；实际演练界面另经真实 UI 测试验证。

## V2.1 实际演练界面
- 预检面板使用实时 getBackup 回调准备世代；明确确认规范化及替换退役记录。用户启动、通过 JSON 文件提交独立草稿、导出当前草稿或完整记录、回退、结束并重新读取已保存世代。文件上限 8 MiB；只写独立数据库，不改旧键。漂移时禁止提交/回退，仍可导出及退役。导出完整记录包含原始键及快照，请妥善保管。
- 复用 snapshotStore.ts 统一单槽 IDB 事务生命周期（严格 durability 提示、旧引擎降级、abort、complete 后完成及连接关闭），保留三个原数据库/存储名及数据格式。相关设置工具及解析器共用按需加载资源；桌面大分包试验导致桌面加载回归，已撤销，保留原桌面边界。预算不变。
- 实际 UI 端到端验证实时候选、草稿下载与重新提交、完整记录下载内容、回退和退役后重载；独立引擎测试固定注入非规范化候选，避免不同环境初始数据形态造成假失败。三方规划已接入独立演练草稿预览，仍未接入生产编辑流程，不能将演练当作完整迁移。

## V2.1 版本化草稿与冲突预览
- 独立草稿 JSON 使用 inftab-rehearsal v1 信封，包含 generation、revision 和可编辑 draft；不接受缺少世代/版本的整份备份作为演练提交。信封不是签名认证，版本来源仅由本地保留记录核对。
- 导入时读取最新世代；仅允许当前 head 或上一保留 revision 为基础，过旧/其他世代拒绝。非冲突修改通过三方规划生成预览，用户确认后使用预览时的 CAS 令牌提交；若期间再次修改，拒绝提交。冲突显示路径及原因，禁止提交，保留原文件并可导出带原版本的未提交草稿；手动修复并重新导入。当前显示前20条路径及总数，不是逐字段可视化编辑器。
- 合并设置工具与 SettingsPanel 及主题验证模块，仍保持首页按需加载。共享规范比较逻辑。资源预算不变，实际生产分包回归验证通过。

## V2.1 独立 origin 权威适配器候选（未接入应用）
- 新增 workspaceAuthority.ts，独立 IDB 库 inftab-workspace-authority/workspace/authority。显式导入迁移候选，保留原始来源与逻辑快照；prepared → active → archived。异步读取仅在 active 且目标无旧数据时返回权威快照；其他状态不允许隐式回落到默认数据或旧库。初始化不可覆盖已有记录；提交、回退、归档统一世代与 revision CAS，head/previous 同事务，配额错误中止。
- 必须是与用户声明的原安装不同的 HTTP(S) origin，目标不能已有任意 inftab.* localStorage 键。每次读取和写入检查旧键，发现旧数据返回 blocked 或拒绝写入，仍可读取记录以供导出或明确归档。不清空旧键、不双写、不自动合并。归档是终止写入，不是把新数据恢复至旧应用。
- 浏览器同源隔离只能保证旧 origin 无法直接访问目标 origin 的存储；需要独立部署并保证旧应用不会在目标 origin 运行（不同 Pages 路径不算隔离）。来源 origin 为调用者声明，不是签名证明，无法检测源站导出之后的编辑。目标同源旧代码仍可写入其自身 localStorage，检查不能保证跨库原子互斥或检测瞬时写入后删除。
- 使用实际预检界面创建候选，真实浏览器第二 origin（测试路由）验收同源拒绝、配额中止、重载准备态、并发 CAS、回退、归档及目标旧键阻塞。仅测试入口打包，不改生产 bootstrap。仍缺显式迁移候选传输 UI、独立 origin 部署决策、全应用异步读取/写入接线与跨浏览器进程终止验收。

## V2.1 独立迁移文件与控制台
- npm run build:migration 独立生成 dist-migration，不加入正式网页、PWA 或扩展产物；按部署环境显式放置于源 origin 与不同目标 origin，禁止在目标运行旧应用。暂不自动部署。控制台使用原生表单，不新增依赖。
- 源站读取已保存迁移候选，检查未完成桌面事务、原始键及候选在导出期间是否变化。文件绑定源和目标 origin、格式版本及 SHA256，保留完整候选。目标按明确输入的源 origin 与当前 origin 检查，验证大小、校验值和候选结构，展示规范化差异，确认后再次验证并准备权威记录。SHA256 不是签名，无法证明源身份或防止蓄意重新计算；文件未加密，含私人数据。
- 目标允许读取、启用、归档、导出独立记录；初始化拒绝覆盖既有记录，不自动启动正式应用。源控制台不能读取尚未持久化的响应式数据，要求先保存候选并关闭其他编辑标签，且不能证明导出后源站无编辑。独立部署与全应用异步接线仍未实施。
- 新增控制台实际构建、双 origin 文件下载/上传、篡改拒绝、目标不匹配、刷新、重复导入、源字节保留与漂移拒绝的浏览器用例；待 CI 实际核验。

## V2.1 异步权威工作区编辑试点
- authoritySession.ts 在 active 权威记录上建立独立 base/draft/token 会话；仅显式保存提交 CAS，错误保留草稿，无默认数据回退。读取并合并最新版本只更新内存草稿，需再次确认保存；冲突保留原草稿和基础版本，可下载。会话期间禁止并行事务；关闭未保存草稿需明确确认，浏览器离开提示仅为尽力保护，不保证崩溃后恢复未提交内存。
- 独立控制台实际接入笔记标题/正文编辑及待办完成状态；不改动其余快照域，不双写旧键。打开会话期间锁定来源切换、初始化、归档入口。此为业务接线试点，不是完整主应用适配器。仍需导入草稿恢复、其余领域、跨浏览器及异常关闭验收。
- 扩展实际控制台双标签 E2E：保存竞争、非冲突合并、同字段冲突与下载草稿。待新CI核验。

## V2.1 持久化恢复草稿
- authorityRecovery.ts 使用独立 IndexedDB inftab-authority-drafts/drafts；每个会话随机 ID，单记录包含源/目标、世代、基础 revision、base/draft，分别经过严格快照验证。最多 8 份、总计 32 MiB；不自动驱逐，配额或损坏拒绝写入，删除按所读记录内容与时间比对。
- 编辑后 700ms 防抖自动检查点，串行写入，完成后才显示已持久化；也可立即保存。权威保存成功或明确关闭放弃后清理本会话记录，不删除其他会话；恢复旧记录复制到新会话 ID，原记录保留直到明确删除。导出和导入支持外部文件，当前/上一版本必须匹配真实保留基础；更旧的外部文件拒绝自动恢复，局部持久化记录可保留更旧基础，但仍需重基与 CAS 提交。
- 仅确认完成的检查点可用于恢复；不保证防抖期间、浏览器强制终止、存储被清除或真实断电后的未落盘数据。pagehide 仅尽力保存。未接正式应用。扩展实际控制台重载恢复与冲突拒绝测试，待 CI。

## 尚未启用的迁移
当前生产仍使用原 localStorage v1 键。不得同时将两种后端作为权威状态，亦不得把新事务数据库当作已经完成迁移的恢复源。
1. 首次迁移前验证并导出旧快照，保留旧数据，持久化迁移标记。跨标签必须一致识别版本，不允许旧标签继续写旧权威状态。
2. 以完整工作区快照为权威，迁移、编辑、恢复统一通过 CAS；引用校验先于提交。读取路径必须等待初始化完成，处理拒绝访问、损坏与版本过旧。
3. 同字段冲突与删除冲突提示、非冲突字段三方合并；失败不覆盖远端且允许导出本地草稿。不要自动合并旧快照复活显式删除的入口。
4. 验证真实浏览器配额、被杀进程、迁移中断、旧版回退与多标签重连；浏览器事务成功不是对真实断电的绝对保证。完整门禁通过再切换生产后端。
